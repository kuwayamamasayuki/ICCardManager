## 0. このドキュメントについて

| 項目 | 内容 |
|------|------|
| **対象読者** | 本システムの開発者・保守担当者。業務フローをオブジェクト間の時系列で追いたい人 |
| **前提知識** | `04_機能設計書.md`(業務仕様) / `05_クラス設計書.md`(登場するクラスの責務) |
| **このドキュメントで答えられる問い** | ・貸出/返却処理の中でクラス間でどうメッセージが飛ぶか<br>・30秒ルールやタイムアウトはどう実装されているか<br>・履歴統合/分割/職員認証のフロー<br>・バックアップ・CSV入出力・印刷プレビューの処理順 |
| **関連ドキュメント** | `04_機能設計書.md`(業務視点) / `05_クラス設計書.md`(実装視点) |

> **Mermaidの読み方**: `participant X as Y` は「X というエイリアスで Y を登場させる」、`A->>B: msg` は同期呼び出し、`B-->>A: resp` は戻り値。`alt` / `loop` / `Note` ブロックで条件分岐・繰り返し・補足を表現します。

> **トランザクション表記について（Issue #1245）**: 本書のシーケンス図では書き込み系処理を `await BeginTransactionAsync()` → `TransactionScope (using)` → `scope.Commit()` の形で表記しています。`scope.Rollback()` は原則として図に出しません — 例外経路では **`scope.Dispose()` が自動的にロールバックする** ためです。この仕様の詳細は [§9.1 TransactionScope の自動ロールバック仕様](#91-transactionscope-の自動ロールバック仕様重要) を参照してください。

## 2. 職員証タッチ〜交通系ICカードタッチのフロー

```mermaid
sequenceDiagram
    autonumber
    participant User as ユーザー
    participant PaSoRi as PaSoRi
    participant Reader as ICardReader
    participant VM as MainViewModel
    participant Sound as ISoundPlayer

    Note over User,Sound: 初期状態: WaitingForStaffCard

    User->>PaSoRi: 職員証をタッチ
    PaSoRi->>Reader: カード検出
    Reader->>VM: CardRead イベント発火(IDm)

    VM->>VM: 職員か・交通系ICカードかを DB で判定
    VM->>VM: 前提の再判定（抑制なし・WaitingForStaffCard のまま。Issue #1842）
    Note right of VM: 判定の await 中に届いた別のタッチが先に<br/>処理を終えていたら、このタッチは何もせず中止
    alt 職員証の場合
        VM->>Sound: Play(SoundType.Notify)
        VM->>VM: 状態を WaitingForIcCard に変更（メイン画面は変えない。Issue #186）
        VM->>VM: 職員証の認識トーストを表示
        VM->>VM: タイムアウトタイマー開始(60秒)
    else 登録済みの交通系ICカード・30秒以内の再タッチ
        VM->>VM: 逆処理を実行（§6。操作者は前回の操作者で補完）
    else 登録済みの交通系ICカード（職員証なしで直接タッチ）
        VM->>VM: 残額の食い違いを判定（Issue #1908）
        VM->>VM: 履歴を表示
    else 未登録のカード
        VM->>VM: 未登録カード処理（§7）
    end

    Note over User,Sound: 状態: WaitingForIcCard

    User->>PaSoRi: 交通系ICカードをタッチ
    PaSoRi->>Reader: カード検出
    Reader->>VM: CardRead イベント発火(IDm)

    VM->>VM: 職員か・交通系ICカードかを DB で判定
    VM->>VM: 前提の再判定（抑制なし・WaitingForIcCard のまま。Issue #1842）
    VM->>VM: タイムアウトタイマー停止

    alt 職員証の場合（持ち替え。Issue #1211）
        VM->>VM: 操作者を上書き（状態は WaitingForIcCard のまま）
        VM->>Sound: Play(SoundType.Notify)
        VM->>VM: 職員証の認識トーストを表示・タイムアウトタイマー再開(60秒)
    else 未登録のカード
        VM->>VM: 未登録カード処理（§7）→ 状態を WaitingForStaffCard に戻す
    else 払戻済の交通系ICカード（Issue #530）
        VM->>Sound: Play(SoundType.Error)
        VM->>VM: エラー通知「払い戻し済みのため貸出できません」→ 状態を WaitingForStaffCard に戻す
    else 30秒以内の再タッチ
        VM->>VM: 逆処理を実行（§6。操作者はいまタッチした職員。台帳の名義は 04 §3.4）
    else 通常処理
        VM->>VM: カードの貸出状態を確認
        alt 未貸出（is_lent = 0）
            VM->>VM: 貸出処理を実行（§3）
            VM->>Sound: Play(SoundType.Lend)
        else 貸出中（is_lent = 1）
            VM->>VM: 返却処理を実行（§4）
            VM->>Sound: Play(SoundType.Return)
        end
    end

    VM->>VM: 状態を WaitingForStaffCard に戻す（持ち替えの場合を除く）
```

> **30秒ルールは職員証タッチ待ちでも働く**: 判定（`IsRetouchWithinTimeout`）は交通系ICカードの IDm しか見ないため、職員証をタッチせずに同じ交通系ICカードを時間内に再タッチしても逆処理になる。誰の操作として記録するかは §6 と 04_機能設計書 §3.4 を参照。

## 3. 貸出処理シーケンス

```mermaid
sequenceDiagram
    autonumber
    participant VM as MainViewModel
    participant Reader as ICardReader
    participant LS as LendingService
    participant SR as IStaffRepository
    participant CR as ICardRepository
    participant LR as ILedgerRepository
    participant DB as DbContext
    participant Sound as ISoundPlayer

    VM->>Reader: ReadBalanceAsync(cardIdm)
    Reader-->>VM: 残高（読み取れなければ null。貸出は続ける。Issue #526）
    VM->>LS: LendAsync(staffIdm, cardIdm, balance)

    LS->>CR: GetByIdmAsync(cardIdm)
    CR->>DB: SELECT FROM ic_card
    DB-->>CR: カード情報
    CR-->>LS: IcCard

    break カード未登録
        LS-->>VM: Error: カードが登録されていません
    end
    break 払戻済（Issue #2322）
        LS-->>VM: Error: このカードは払い戻し済みのため貸出できません
    end
    break カード貸出中
        LS-->>VM: Error: このカードは既に貸出中です
    end

    LS->>SR: GetByIdmAsync(staffIdm)
    SR->>DB: SELECT FROM staff
    DB-->>SR: 職員情報
    SR-->>LS: Staff

    break 職員未登録
        LS-->>VM: Error: 職員証が登録されていません
    end

    LS->>LS: ResolveInitialBalanceAsync(cardIdm, balance)
    opt 残高を読み取れなかった（balance = null。Issue #656）
        LS->>LR: GetLatestLedgerAsync(cardIdm)
        LR-->>LS: 直近の履歴（その残額で補う。履歴が無ければ 0）
    end

    LS->>DB: await BeginTransactionAsync()
    DB-->>LS: TransactionScope (using)
    Note over LS,DB: 以降の DB 操作は TransactionScope 内で実行

    LS->>LR: InsertAsync(Ledger)
    Note right of LR: summary = SummaryGenerator.GetLendingSummary()<br/>（組織設定の文言。既定は「（貸出中）」）<br/>is_lent_record = true（貸出中かは摘要ではなくこのフラグで判定。Issue #2044）
    LR->>DB: INSERT INTO ledger
    DB-->>LR: ledgerId
    LR-->>LS: ledgerId

    LS->>CR: UpdateLentStatusAsync(cardIdm, true, now, staffIdm)
    CR->>DB: UPDATE ic_card SET is_lent = 1<br/>WHERE is_deleted = 0 AND is_refunded = 0
    DB-->>CR: success
    CR-->>LS: success
    Note over LS,CR: 0 行なら競合。カードを読み直し、払戻済なら BIZ018、<br/>それ以外は BIZ015 を投げてトランザクションごと巻き戻す（Issue #1953 / #2322）

    LS->>DB: scope.Commit()
    Note over LS,DB: using 脱出時に scope.Dispose() が<br/>トランザクションとリースを順次解放

    LS->>LS: LastProcessedCardIdm = cardIdm
    LS->>LS: LastProcessedTime = now
    LS->>LS: LastOperationType = Lend

    LS-->>VM: LendingResult(Success = true)

    VM->>Sound: Play(SoundType.Lend)
    VM->>VM: 画面表示更新（貸出完了）
```

## 4. 返却処理シーケンス

```mermaid
sequenceDiagram
    autonumber
    participant VM as MainViewModel
    participant Reader as ICardReader
    participant LS as LendingService
    participant SR as IStaffRepository
    participant CR as ICardRepository
    participant LR as ILedgerRepository
    participant SG as SummaryGenerator
    participant DB as DbContext
    participant Set as ISettingsRepository
    participant Sound as ISoundPlayer

    VM->>Reader: TryReadHistoryAsync(cardIdm)
    Reader-->>VM: CardReadResult<IReadOnlyList<LedgerDetail>>（Success / Value / Error）
    Note right of VM: 読み取りに失敗した・途中でカードが離れた場合は<br/>エラー通知して返却しない（Issue #1169 / #2301）

    VM->>LS: ReturnAsync(staffIdm, cardIdm, usageDetails)

    LS->>CR: GetByIdmAsync(cardIdm)
    CR-->>LS: IcCard(is_lent = true)

    LS->>SR: GetByIdmAsync(staffIdm)
    SR-->>LS: Staff

    LS->>LR: GetLentRecordAsync(cardIdm)
    LR->>DB: SELECT FROM ledger WHERE is_lent_record = 1
    DB-->>LR: 貸出レコード
    LR-->>LS: Ledger

    LS->>LR: GetPurchaseDateAsync(cardIdm)
    LR-->>LS: 導入行の日付（無ければ null）
    LS->>LR: GetLatestLedgerDateWithoutDetailsAsync(cardIdm)
    LR-->>LS: 明細を持たない利用行の最新日（無ければ null）
    LS->>LS: 導入行の日付以降の利用履歴を抽出（導入行が無ければ貸出日の7日前以降。明細を持たない利用行があればその翌日以降。ただし貸出日を超えない。Issue #2237）
    LS->>LR: GetByMonthAsync(cardIdm, 今年, 今月)
    LR-->>LS: 今月の既存の行（履歴の完全性チェック用。Issue #596）

    LS->>DB: await BeginTransactionAsync()
    DB-->>LS: TransactionScope (using)

    loop 日付ごとにグループ化
        alt チャージあり
            LS->>LR: InsertAsync(ChargeLedger)
            Note right of LR: summary = GetChargeSummary(部局種別)<br/>（「役務費によりチャージ」、企業会計部局は「旅費によりチャージ」）
        end

        alt 利用あり
            LS->>SG: Generate(usageDetails)
            SG-->>LS: "鉄道（A駅～B駅）"
            LS->>LR: InsertAsync(UsageLedger)
            LS->>LR: InsertDetailsAsync(ledgerId, details)
        end
    end

    Note right of LS: 利用・チャージの行の名義（lender_idm・staff_name）は<br/>貸出レコードの貸出者。返却した職員ではない（Issue #2323）

    LS->>LR: DeleteAllLentRecordsAsync(cardIdm)
    Note right of LR: 貸出中レコードは物理削除する（更新して残さない）。<br/>共有モードで重複した貸出中レコードもまとめて消す

    LS->>CR: UpdateLentStatusAsync(cardIdm, false, null, null)
    Note over LS,CR: 0 行なら競合。トランザクションごと巻き戻す（Issue #1953）

    LS->>DB: scope.Commit()
    Note over LS,DB: using 脱出時に scope.Dispose() が<br/>トランザクションとリースを順次解放

    opt 今月の既存の行が無かった
        LS->>LS: CheckHistoryCompleteness（DB I/O なし）→ MayHaveIncompleteHistory
    end

    LS->>LS: バス利用チェック
    alt バス利用あり
        LS->>LS: HasBusUsage = true
    end

    LS->>LS: 30秒ルール用の処理情報を記録・Success = true
    Note right of LS: Issue #1805: ここで返却は確定。<br/>以降の後処理の失敗で Success は落とさない

    LS->>LS: 残高チェック（残額の解決・残額警告の付与）
    alt 残高がしきい値以下（BalanceWarningPolicy.IsLowBalance、Issue #1998）
        LS->>LS: IsLowBalance = true
    else 残額の解決・残額警告の DB I/O で例外
        LS->>LS: HasPostCommitFailure = true（Success は true のまま）
    end

    LS-->>VM: LendingResult(Success = true)

    alt HasPostCommitFailure
        VM->>Sound: Play(SoundType.Warning)
        VM->>VM: 「返却は記録済み／残額を確認できませんでした。再タッチしないでください。」
    else
        VM->>Sound: Play(SoundType.Return)
        VM->>VM: 残額付きの返却通知（残額がしきい値以下なら「⚠️ 残額不足（N円以下）」の補足行。警告音は鳴らさない）
    end

    VM->>VM: ダッシュボード更新（警告アイコンと残額警告 LowBalance を同じしきい値で作り直す）

    VM->>Set: GetAppSettingsAsync()
    Set-->>VM: AppSettings（返却後の 3 つの入力・表示で共有する。読むのは 1 回だけ。Issue #1805）

    alt バス利用あり かつ バス停名入力をスキップしない設定
        VM->>VM: バス停名入力ダイアログを表示（対象の行があれば）
    end

    alt 同行者数の入力対象の行あり かつ スキップしない設定（Issue #1906）
        VM->>VM: 同行者数入力ダイアログを表示
        Note right of VM: 無操作なら既定 30 秒で「外0名」として閉じる（Issue #2009）
    end

    VM->>VM: History.ShowReturnHistoryReviewAsync(card, result, settings)
    Note right of VM: 返却確認（Issue #1907）。設定 ShowHistoryOnReturn（既定 有効）なら<br/>返却したカードの履歴を表示し、今回記録した行を強調する。<br/>閉じる契機は次の職員証タッチ

    opt MayHaveIncompleteHistory
        VM->>VM: 警告トースト「履歴の確認」（今月の利用履歴がすべて取得できていない可能性。CSV インポートで補完を案内）
    end
```

```mermaid
        RS-->>VM: ReportGenerationResult（Created）
    end

    VM->>VM: 作成・作成対象外・失敗を別々に数えて完了メッセージ表示
    VM-->>User: 作成完了
```

## 6. 30秒ルール適用シーケンス

```mermaid
sequenceDiagram
    autonumber
    participant User as ユーザー
    participant VM as MainViewModel
    participant Reader as ICardReader
    participant LS as LendingService
    participant Sound as ISoundPlayer

    Note over User,Sound: 前提: 直前に貸出処理を実行済み<br/>LastProcessedCardIdm = "CARD001"<br/>LastOperationType = Lend

    User->>VM: 同じカードを再タッチ（30秒以内）

    VM->>LS: IsRetouchWithinTimeout("CARD001")
    LS->>LS: LastProcessedCardIdm == cardIdm?
    LS->>LS: (Now - LastProcessedTime) <= 30秒?
    LS-->>VM: true

    VM->>VM: 操作者を決定（Issue #1729）

    alt _currentStaffIdm が確定済み（直前に職員証タッチ）
        Note over VM: いまタッチした職員をそのまま使う<br/>前回操作者で上書きしない
    else 未確定（職員証タッチ待ちからの再タッチ）
        VM->>VM: _currentStaffIdm = _lastProcessedStaffIdm
        Note over VM: 前回操作者も未設定ならエラー通知して中断
    end

    VM->>VM: LastOperationType を確認

    alt LastOperationType == Lend
```

## 9. エラー処理シーケンス

### 9.1 TransactionScope の自動ロールバック仕様（重要）

`DbContext.BeginTransactionAsync()` が返す `TransactionScope` は RAII 的なラッパーであり、**`using` を抜けた時点で `scope.Commit()` も `scope.Rollback()` も呼ばれていなければ `Dispose()` が自動的にロールバックする**。

このため、例外経路での明示的な `Rollback()` 呼び出しは**不要**である（呼んでも冗長になるだけ）。

- 正常系: `scope.Commit()` → トランザクション確定
- 例外系: 例外が `using` 文を突き抜ける → `scope.Dispose()` が自動ロールバック
- 明示ロールバック: `scope.Rollback()` は "明示的にロールバックしたい" ことを意図的に示す場合のみ使用（可読性向上）

詳細は [`05_クラス設計書.md` §5.5b 接続リース・トランザクションスコープ](05_クラス設計書.md#55b-接続リーストランザクションスコープissue-1243) を参照。

### 9.2 エラー処理シーケンス図

```mermaid
sequenceDiagram
    autonumber
    participant VM as MainViewModel
    participant LS as LendingService
    participant DB as DbContext
    participant Sound as ISoundPlayer

    VM->>LS: LendAsync(staffIdm, cardIdm, balance)

    LS->>DB: await BeginTransactionAsync()
    DB-->>LS: TransactionScope (using)

    LS->>LS: 処理実行中...

    alt 正常系
        LS->>DB: scope.Commit()
        Note over LS,DB: using 脱出時に Dispose() が<br/>トランザクション→リースの順で解放
        LS-->>VM: LendingResult(Success = true)
    else データベースエラー発生
        Note over LS: 例外が using を突き抜ける
        Note over LS,DB: scope.Dispose() が<br/>自動ロールバック（Rollback 不要）
        LS-->>VM: LendingResult(Success = false, ErrorMessage)
    end

    alt Success = false
        VM->>Sound: Play(SoundType.Error)
        VM->>VM: ShowError（エラー通知のトースト。メイン画面は変えない。Issue #186）

```

```mermaid
    end

    Note over MS,DB: using 脱出時に scope.Dispose() が<br/>トランザクションとリースを順次解放
```

> **競合検出は影響行数で行う（Issue #1753）**: 読み取り（`GetByIdAsync`）と書き込み（`MergeLedgersAsync`）は別トランザクションのため、共有モードではその間に他 PC が同じ履歴を統合・削除し得る。行ロックを持たないため、書き込み時の影響行数で競合を検出する（楽観ロック）。詳細と適用範囲は `05_クラス設計書.md` §5.5b「更新・削除は影響行数で競合を検出する」を参照。

> **統合の取り消しも認証を経る（Issue #2265）**: 統合の取り消し（`ConfirmAndExecuteUnmergeAsync`）は、取り消す統合の確認で「はい」を選んだ後に `RequestAuthenticationAsync("統合の取り消し")` を呼び、認証結果を `Enter()` したスコープの中で `LedgerMergeService.UnmergeAsync` を実行する（本図の統合と同じゲート）。認証が完了しなければ台帳を書き戻さない。取り消しは台帳の書き戻し・取り消し済みのマークと同じトランザクションで `LogLedgerUnmergeAsync`（操作種別 `UNMERGE`）を記録し、記録に失敗したら取り消しごと巻き戻る（04_機能設計書 §14.4）。

```mermaid
    Note right of BS: 手動バックアップは世代削除をしない

    VM->>OL: LogBackupAsync(path)
    Note right of VM: 記録の失敗はバックアップの失敗として通知しない（Issue #2130）
    VM->>VM: バックアップ一覧を再読込
    VM-->>User: 完了メッセージ
```

### 13.3 リストア

```mermaid
sequenceDiagram
    autonumber
    participant User as ユーザー
    participant VM as SystemManageViewModel
    participant Auth as StaffAuthService
    participant BS as BackupService
    participant DB as DbContext
    participant OL as OperationLogger

    User->>VM: リストアボタンクリック（一覧で選択、またはファイルを指定）
    Note right of VM: 一覧から選んだ場合は、押した時点のファイルを<br/>操作対象として確定させる（Issue #1761）

    VM->>Auth: RequestAuthenticationAsync("データベースのリストア")
    Auth-->>VM: StaffAuthResult（Enter() したスコープの中で以降を実行）
    break 認証が完了しない
        VM-->>User: 「認証がキャンセルされたため、リストアを中止しました」
    end

    VM-->>User: 確認ダイアログ（共有モードでは全PCの終了を促す。Issue #1108）
    break いいえ
        VM-->>User: 中止
    end

    VM->>BS: PrepareRestoreSourceAsync(sourcePath)
    Note right of BS: 専用スレッドで実行。リストア元を一時フォルダへコピーし、<br/>ヘッダ・切り詰め（Issue #1748）・PRAGMA quick_check・<br/>本システムの DB の印・SchemaObjectInspector・<br/>スキーマの版を検証する（Issue #2269）
    BS-->>VM: RestoreSourceValidationResult（合格なら一時コピーを持つ）
    break 不合格
        VM-->>User: 不合格の理由と対処（本番 DB は変更しない）
    end

    VM->>BS: CreateBackupAsync(backup_pre_restore_….db)
    BS-->>VM: リストア前バックアップの成否
    opt 失敗
        VM-->>User: 「バックアップなしでリストアを続行しますか？」
        break いいえ
            VM-->>User: 「リストアをキャンセルしました」
        end
    end

    VM->>BS: RestoreFromPreparedSourceAsync(prepared)
    Note right of BS: Issue #1809: Task.Run で同期版を委譲（SuspendConnections が<br/>セマフォを同期取得するため UI スレッドでは<br/>#1281 のガードで拒否される）
    BS->>DB: SuspendConnections()
    Note right of DB: 接続セマフォを取得し進行中の<br/>トランザクション・リースの完了を待ってから<br/>SQLite接続を閉じてファイルロックを解除（Issue #1809）。<br/>停止中に到着した書き込みは解除まで待機
    alt 共有モードで排他ロックを取れない（CanAcquireExclusiveLock。他PCが接続中）
        BS-->>VM: false（本番 DB は変更しない）
    end
    BS->>BS: 現在のDBを.tempに退避（File.Move）
    BS->>BS: 検証済みの一時コピー → DBパスへ File.Copy

    alt コピー成功
        BS->>BS: CleanupJournalFiles（古い -wal / -shm を消す）
        BS->>BS: .tempファイル削除
        BS-->>VM: true
    else コピー失敗
        BS->>BS: .tempから元のDBを復元
        BS-->>VM: false
    end

    alt 成功
        VM->>OL: LogRestoreAsync(sourcePath)
        Note right of VM: 記録に失敗しても「リストアは完了」と伝え、<br/>記録できなかったことを併記する（Issue #2130）
        VM-->>User: 「リストアが完了しました。アプリケーションを再起動してください。」
    else 失敗
        VM-->>User: 失敗の理由と対処（共有モードでは他PCの終了を案内）
    end
```

```mermaid
sequenceDiagram
    autonumber

        VM->>Exp: ExportStaffAsync(filePath, includeDeleted)

        SR-->>Exp: List~Staff~

        Exp->>LR: GetByDateRangeAsync(cardIdm = null, startDate, endDate)
        LR-->>Exp: List~Ledger~
        Exp->>Exp: 貸出中レコードを除いて CSV書き出し（Issue #2307）
        Exp-->>VM: CsvExportResult(出力件数)
    end

    VM-->>User: 完了メッセージ（X件出力）

    Note over User,DB: CSVインポート（職員データの例）

    User->>VM: プレビューボタンクリック（ファイル選択済み）

    VM->>Imp: PreviewStaffAsync(filePath, skipExisting)
    Imp->>Imp: CSVパース → バリデーション → 既存データとの照合
    Imp-->>VM: CsvImportPreviewResult
    VM->>VM: 取り込みの条件とファイルの状態をプレビューと一緒に記録（Issue #2262）

    VM-->>User: プレビュー表示

    User->>VM: インポート実行
    VM->>VM: プレビューした条件と、いまの条件を照合（違えばプレビューを破棄）

    VM->>Auth: RequestAuthenticationAsync("職員のインポート")
    Note right of VM: 登録済みの職員が 0 人なら認証を求めない。<br/>利用履歴は「利用履歴のインポート」、<br/>利用履歴詳細は「利用履歴詳細のインポート」
    Auth-->>VM: StaffAuthResult（Enter() したスコープの中で取り込む）
    break 認証が完了しない
        VM-->>User: 取り込んでいない旨と、やり直し方
    end

    VM->>VM: ファイルがプレビューから変わっていないか照合（変わっていれば中止）

    VM->>Imp: ImportStaffAsync(filePath, skipExisting)
    Imp->>Imp: CSVパース → バリデーション → 既存データとの照合
    break バリデーションエラーがある
        Imp-->>VM: CsvImportResult(Success = false, エラー)
        Note right of Imp: トランザクションを始める前に返る（何も書き込まない）
    end
    Imp->>DB: await BeginTransactionAsync()
    DB-->>Imp: TransactionScope (using)
    loop 取り込む行ごと
        Imp->>SR: InsertAsync / UpdateAsync / RestoreAsync(…, tx)
        Imp->>OL: LogStaffInsertAsync / LogStaffUpdateAsync / LogStaffRestoreAsync(…, tx)
    end
    alt エラーが 1 件も無い
        Imp->>DB: scope.Commit()
    else エラーあり
        Note over Imp,DB: コミットしない（scope.Dispose() で全行を巻き戻す）
    end
    Imp-->>VM: CsvImportResult(登録件数, 更新件数, スキップ件数, エラー)

    alt 成功
        VM->>OL: LogImportAsync(対象テーブル, filePath, 新規件数, 更新件数, …)
    else 一部だけ取り込めた（登録件数が 1 件以上）
        VM->>OL: LogImportAsync(対象テーブル, filePath, 新規件数, 更新件数, …)
    else 何も取り込めなかった
        Note right of VM: 取り込み全体の操作ログは記録しない
    end
    Note right of VM: 取り込み全体の記録。記録に失敗しても取り込みの失敗として通知しない
    VM-->>User: 結果メッセージ
```
